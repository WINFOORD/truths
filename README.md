# دو دروغ و یک حقیقت

نسخه‌ی Vercel-ready با لینک دعوت اختصاصی، نشست امن سمت سرور و اعلان تلگرام.

## 1) آماده‌سازی Supabase

1. از بخش SQL Editor فایل `supabase-migration.sql` را اجرا کن.
2. این migration جدول‌های فعلی را حذف نمی‌کند و اطلاعات مهمان‌ها، سؤال‌ها و جواب‌ها را نگه می‌دارد.
3. دسترسی مستقیم `anon` و `authenticated` به جدول‌ها بسته می‌شود. از این نسخه به بعد مرورگر فقط از APIهای سرور استفاده می‌کند.
4. کلید Service Role فقط باید در Environment Variables سمت سرور باشد؛ هرگز آن را با پیشوند `VITE_` تعریف نکن.

> فایل‌های `supabase.sql` و `supabase-first-time.sql` برای نصب اولیه‌ی قدیمی هستند و جدول‌ها را حذف و دوباره می‌سازند. برای دیتابیس فعلی اجرا نکن.

## 2) متغیرهای Vercel

در Project Settings → Environment Variables این مقادیر را تنظیم کن:

| Variable | توضیح |
|---|---|
| `SUPABASE_URL` | آدرس پروژه Supabase |
| `SUPABASE_SERVICE_KEY` | کلید محرمانه‌ی Service Role / Secret |
| `HOST_PIN` | رمز ورود میزبان؛ حداقل ۱۲ کاراکتر پیشنهاد می‌شود |
| `HOST_NAME` | نام میزبان، مثلاً علی |
| `SESSION_SECRET` | رشته‌ی تصادفی محرمانه با حداقل ۳۲ کاراکتر |
| `VITE_BOT_USERNAME` | نام کاربری ربات بدون @ |
| `TELEGRAM_BOT_TOKEN` | توکن ربات تلگرام |
| `TELEGRAM_WEBHOOK_SECRET` | رشته‌ی تصادفی محرمانه برای وب‌هوک |
| `TELEGRAM_HOST_CHAT_ID` | شناسه‌ی عددی چت میزبان با ربات |

برای ساخت secret تصادفی می‌توانی از دستور زیر استفاده کنی:

```bash
openssl rand -hex 32
```

`VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` دیگر در فرانت‌اند استفاده نمی‌شوند.

## 3) اتصال تلگرام

1. ربات را در تلگرام باز کن و `/start` بفرست؛ شناسه‌ی چت را دریافت می‌کنی.
2. شناسه را در `TELEGRAM_HOST_CHAT_ID` در Vercel قرار بده.
3. آدرس وب‌هوک را با جایگزین‌کردن مقادیر واقعی تنظیم کن:

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://YOUR_DOMAIN/api/telegram","secret_token":"YOUR_TELEGRAM_WEBHOOK_SECRET"}'
```

4. بعد از Deploy، در پنل میزبان یک مخاطب بساز. برای هر مخاطب دو لینک مجزا داری:
   - لینک دعوت اختصاصی برای ورود به بازی.
   - لینک اتصال تلگرام برای فعال‌کردن اعلان‌ها.

اعلان سؤال جدید مهمان و پیام خصوصی به چت میزبان می‌آید. سؤال جدید میزبان به مخاطب‌هایی که ربات را متصل کرده‌اند ارسال می‌شود.
بعد از اینکه مخاطب به همه‌ی سؤال‌های میزبان جواب داد، میانگین پاسخ‌های درست و جواب‌هایش هم به همین چت تلگرام فرستاده می‌شود. برای این قابلیت، migration بالا باید پس از اضافه‌شدن ستون `reported` به جدول جواب‌ها اجرا شده باشد.
اگر migration را قبلاً اجرا کرده‌ای، فایل `supabase-migration.sql` را دوباره در SQL Editor اجرا کن تا ستون جدید اضافه شود؛ اسکریپت برای اجرای مجدد طراحی شده است.

## 4) اجرای پروژه

```bash
pnpm install
pnpm build
```

برای توسعه‌ی محلی همراه با APIهای Vercel از `pnpm dlx vercel dev` استفاده کن؛ اجرای صرف `vite`، مسیرهای `/api/*` را اجرا نمی‌کند. اجرای `pnpm dev` در پورت ۵۱۷۳ درخواست‌های `/api/*` را به نسخه‌ی منتشرشده‌ی `truths-iota.vercel.app` می‌فرستد؛ بنابراین تغییر API محلی تا زمان Deploy روی آن دامنه اثر نمی‌گذارد. برای استفاده از API محلی همراه با Vite، در `.env.local` مقدار `VITE_API_PROXY_TARGET=http://localhost:3000` بگذار و `vercel dev` را روی پورت ۳۰۰۰ اجرا کن. متغیرهای محیطی را در `.env.local` قرار بده؛ فایل‌های `.env*` به‌جز `.env.example` در Git نادیده گرفته می‌شوند.

## نکات امنیتی

- نشست ورود در کوکی `HttpOnly` و امضاشده‌ی سمت سرور نگه‌داری می‌شود.
- لینک دعوت هر مخاطب توکن تصادفی اختصاصی و بدون تاریخ انقضا دارد؛ تا وقتی مخاطب در پنل میزبان حذف نشده باشد، لینک معتبر می‌ماند. مخاطب می‌تواند لینک خود را از بخش «من» دوباره کپی کند؛ تاریخ تولد دیگر روش ورود نیست.
- نشست مهمان پس از ۳۰ روز منقضی می‌شود، اما لینک اختصاصی او منقضی نمی‌شود و با بازکردن دوباره‌ی آن می‌تواند وارد شود.
- دسترسی هر مهمان به داده‌ها در API سمت سرور محدود می‌شود.
- `HOST_PIN` و `SESSION_SECRET` و کلیدهای Supabase و تلگرام نباید در کد فرانت‌اند یا Git قرار بگیرند.
- اگر قبلاً فایل `.env` یا کلیدهای محرمانه را در مخزن عمومی قرار داده‌ای، آن کلیدها را از پنل سرویس‌ها Rotate کن.

## نسخه‌ی ۴: بخش‌های جدید

1. فایل `supabase-v4.sql` را یک بار در SQL Editor اجرا کن (داده‌ها حفظ می‌شوند).
2. بعد از Deploy، در «من ← تنظیمات» نیازی به کار اضافه نیست. دسترسی هر مخاطب (خانه، بازی، انتخاب، قرار) از تب «خانه» و تب «قرار» (حساب میزبان) تنظیم می‌شود.
3. نقشه از OpenStreetMap استفاده می‌کند و به کلید یا متغیر اضافه نیاز ندارد.
4. مسیر `/api/hub` فقط روی Vercel وجود دارد؛ تا Deploy نشود، در حالت `pnpm dev` همان نسخه‌ی قبلی منتشرشده جواب می‌دهد.


## نسخه ۵: تجربه‌ی مهمان «بین خودمون»

در این نسخه مسیر مهمان از یک تجربه‌ی چندتبّه به یک بازی مرحله‌ای تبدیل شده است:

1. دعوت‌نامه‌ی شخصی و صفحه‌ی شروع کوتاه.
2. حدس زدن دو دروغ از سه جمله‌ی میزبان؛ با نمایش داستان حقیقت.
3. انتخاب‌های دونفره و مقایسه‌ی انتخاب مهمان با میزبان.
4. ساخت چالش «دو دروغ و یک حقیقت» توسط مهمان برای میزبان (اختیاری).
5. کارت نتیجه با امتیاز حدس‌ها و تعداد انتخاب‌های مشترک؛ امکان اشتراک‌گذاری متن نتیجه.

پیش از ارسال لینک دعوت، پیشنهاد می‌شود میزبان برای هر مهمان ۳ تا ۵ سؤال «دو دروغ و یک حقیقت» و حدود ۵ انتخاب دونفره بسازد؛ در غیر این صورت بعضی مرحله‌ها با امکان رد کردن نمایش داده می‌شوند. پنل میزبان، APIها، ورود با لینک دعوت، ساختار Supabase و اعلان‌های تلگرام حفظ شده‌اند. مهمان برای دیدن پیام‌ها و امکانات جانبی می‌تواند از دکمه‌ی «پیام‌ها و پروفایل» وارد رابط قبلی شود و با «بازگشت به بازی» دوباره به مسیر اصلی برگردد.

پیشرفت مرحله‌ی مهمان در مرورگر ذخیره می‌شود. پاسخ‌های بازی همچنان در Supabase ذخیره می‌شوند و با باز کردن دوباره‌ی لینک، سؤال‌هایی که قبلاً پاسخ داده شده‌اند دوباره نمایش داده نمی‌شوند.
